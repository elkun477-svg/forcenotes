The Winter '27 Security Change That Could Quietly Break Your Integrations

Winter '27 is enforcing the retirement of the OAuth 2.0 username-password flow for connected apps. It's a high-priority release update — and if your integrations still rely on it, they will stop working when enforcement lands.

Most of the Winter '27 release articles focus on the shiny stuff: Flow updates, the new SLDS 2 styling, Agentforce features. But buried in the release updates section is a change that has nothing visually interesting about it — and could cause real problems in production orgs that haven't prepared.

The change: Salesforce is retiring the OAuth 2.0 username-password grant type for connected apps. When this is enforced, connected apps that authenticate by sending a username and password directly via the OAuth token endpoint will fail. This includes a large number of legacy integrations, middleware configurations, and older API clients that were set up before more secure authentication patterns became standard.

To understand why this matters, a quick primer: OAuth is the system Salesforce uses to let other applications connect to your org securely without handing over a raw username and password every time. There are several OAuth "flows" (also called grant types), and the username-password flow is the oldest and simplest — your system sends a username, password, and security token to Salesforce's token endpoint, and Salesforce hands back an access token. The problem is that it's less secure than modern alternatives: it requires storing credentials in your external system, and it doesn't support multi-factor authentication.

The recommended replacement is the OAuth 2.0 JWT Bearer Token flow or the Web Server flow, depending on your use case. JWT is the preferred route for server-to-server integrations because it uses a certificate for authentication instead of a password, which is harder to steal and easier to rotate. If you're auditing your org, the best place to look is your Connected Apps list in Setup, filtered for apps using the username-password grant.

Why this matters if you're learning Salesforce: Authentication and connected apps are core topics in the Developer and Architect tracks. The OAuth flows aren't just exam content — they come up constantly when you're integrating Salesforce with other systems. Understanding why the username-password flow is being retired (and what to use instead) is exactly the kind of security reasoning that separates someone who can configure an integration from someone who understands what they're doing.
