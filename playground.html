Press Run to compile and run your Apex.

Apex Lab is a simulator that runs in your browser: no Salesforce org is involved, so SObjects, SOQL, DML and other org metadata aren’t available. Sets and Maps keep insertion order here, which Salesforce does not guarantee.

Null's tip: break things on purpose. Delete a closing tag or misspell a CSS property and watch what happens. That's how bugs like me are found.

How this works

  • Everything runs inside your browser. Nothing you type is sent anywhere.
  • Save keeps your code in this browser. Copy share link packs your code into a link you can send to a friend.
  • console.log() output shows up in the Console under the preview.
  • HTML / CSS / JS runs in a sandboxed preview. These are the web languages Lightning Web Components are built from.
  • Apex runs on Apex Lab, a small Apex compiler and interpreter written for this site. It checks your code the way Salesforce would (unknown variables, missing methods, wrong types, missing returns, classes that don't implement an interface) and then runs it, showing System.debug output and uncaught exceptions with line numbers. It covers the language itself: classes, interfaces, inheritance, enums, switch, collections, exceptions, properties, inner classes and iterators.
  • Apex Lab has no org, so anything that needs metadata is rejected with a clear message: SObjects like Account, SOQL/SOSL, DML, triggers, Test and Database. For those, use a free Trailhead Playground and the Developer Console. Salesforce’s own compiler is always the final judge.
